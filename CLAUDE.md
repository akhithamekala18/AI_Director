## 5. Code Conventions Actually Detected

Evidence: the single Python script under `docs/` — the 409-line `build_pdf.py`.

- **Encoding header:** every script begins with `# -*- coding: utf-8 -*-`.
- **Constants:** module-level settings are `UPPER_SNAKE_CASE` (`SRC`, `OUT`, `FONTS`, `DEJAVU`, `PAGE_W`, `PAGE_H`, `MARGIN`, `USABLE`, `COVER_VERSION`, `COVER_DATE`).
- **Script shape:** top-level executable scripts with globals and bare top-level code; no `if __name__ == '__main__'` guard; helper functions defined before use.
- **Function naming:** short, verb-first, lowercase helpers, often single-purpose and terse (`st`, `inline`, `parse_blocks`, `flush_para`, `table_flowable`, `code_flowable`, `col_widths`, `natural_width`, `is_sep`, `cover_flowables`).
- **Imports:** multi-symbol `from X import (a, b, c)` grouped per library; stdlib imports first, third-party after (e.g., `import re, os, sys` then `from reportlab... import ...`).
- **Section organization:** divider comments like `# -------------------------------- fonts` group each script into labeled sections (fonts / styles / markup / parse / tables / cover / doc / story).
- **ReportLab patterns:** `ParagraphStyle` objects built through a tiny factory function; tables via `Table` + `TableStyle` with tuple commands; colors via `colors.HexColor('#XXXXXX')`; fonts via `pdfmetrics.registerFont(TTFont(...))` plus `registerFontFamily(...)`.
- **Markdown handling:** custom lightweight parsing in `build_pdf.py` (manual block splitter + regex inline pass that escapes `&`, `<`, `>` before applying `**bold**` / `*italic*` / `` `code` `` / `[text](url)`).
- **File I/O:** Markdown sources are opened with `encoding='utf-8'`.
- **Windows paths:** absolute paths written as raw strings (`r"C:\Windows\Fonts"`).
- **Doc filename naming:** kebab-case Markdown (`ai_director_overview.md`, `prd-automatic-upload.md`, `DEVELOPMENT_PLAN.md`).
